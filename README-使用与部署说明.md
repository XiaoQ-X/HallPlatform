# 霍尔效应教学平台 v1.4

项目位于 `D:\开发项目\最终平台\HallPlatform`。原压缩包在上一级 `原始备份` 中，未修改。本交付包含 Web 平台、两个可重建的 Unity 源工程和与源码成套的 WebGL 产物：核心工作台使用 Unity `2022.3.62f3c1`，微观机理演示使用 Unity `6000.6.1f1`。前端权限、计分、数据保存、教学流程以及 Unity 接线撤销、读数显示和响应式布局均已纳入当前基线；实机标定仍需由课程方用实际仪器复核。

## 本机运行

本机已安装依赖并构建，修复版当前运行于 http://127.0.0.1:8182 。运行 `启动平台.ps1` 默认使用8182；直接执行 `node --experimental-sqlite server/index.js` 则默认使用8181。端口被占用时先设置环境变量 `PORT` 为其他空闲端口。默认只监听本机。

旧公开密码已锁定。管理员执行 `node create-teacher.js teacher 教师1 --reset`，为现有教师生成新的随机密码。仅新建时省略 `--reset`。凭据写入 `data/initial-access.txt`，不会输出到普通日志；登录后修改密码并删除凭据文件。教师在学生管理中创建学生或重置旧学生密码（至少6位）。注册接口已关闭。不要重置已经改过的正常账号。

## 安装与维护

测试环境为 Windows、Node 24.19.0、pnpm 11.19.0。需要 Node >=22.13，其他系统及Node版本应另做验收。

```text
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm start
pnpm audit
```

`pnpm-lock.yaml` 是唯一依赖锁文件，移除了过时 npm 锁文件。安装和审计需要网络或已准备完整 pnpm 离线仓库；仅拷贝源码不能离线安装。运行时前端资源及 Unity 产物均本地托管。跨操作系统应重新安装依赖并构建，不能保证拷贝 node_modules 可用。升级依赖后需重跑回归与浏览器测试。`tests/browser-smoke.cjs` 使用本机 Codex 配套 Playwright 路径与 Edge，在其他机器运行需修改依赖定位。

## Unity 仿真构建与物理口径

核心工作台源工程位于 `unity/HallCore-WebHandoff-2.3.0-web.1`，使用 Unity `2022.3.62f3c1` 和 WebGL Build Support；构建入口为 `Tools/Build-WebGL.ps1` 的 `HallLab.Editor.WebPlayerBuild.Build`。微观机理源工程位于 `unity/MicroLab-WebHandoff-1.0.0`，必须使用 Unity `6000.6.1f1`，构建入口为 `HallEffectLab.EditorTools.HallWebGLBuild.Build`。两个工程的 `Library`、临时目录和历史构建不纳入源码；当前页面使用 `public/sim/Build` 与 `public/sim/case-microscopic/Build` 下同一批 loader/data/framework/wasm 文件，更新时必须整套替换并同步页面版本号。

核心工作台的标准采样顺序是断电接线、检查回路、归零开机、等待稳定、四方向记录，再由网页按
`VH = (V1 - V2 + V3 - V4) / 4` 合成。四方向原始读数包含不等位电势、热电和噪声等模型分量，不能直接当作理想霍尔电压；`IM` 也不能未经磁场标定直接当作 `B`。微观演示采用归一化教学单位，页面明确相机与 `+Z` 方向约定；`B = 0` 时横向洛伦兹力、霍尔场和电荷面均为零，达到 8 s 后显示完成并需重置才能重新演示。这些模型用于教学可视化，不替代真实仪器的零点、量程、标定和不确定度校准。

副效应教学页明确采用四项横向磁效应 `V⊥ = VH + VE + VN + VRL`，实测量为 `Vmeasured = V⊥ + V0 + Voffset`。四方向对称组合消除 `V0、VN、VRL` 与固定零点，保留与 `VH` 具有相同换向规律的 `VE`；只有已知 `kE` 或独立温差标定时，才能由 `Vcorr − VE` 得到理想 `VH`。

建议在修改 Unity 源码后依次执行 `pnpm test`、`pnpm build` 和 `node tests/browser-smoke.cjs`，再分别在桌面 Edge/Chrome 以 1280×800 以上窗口检查两个场景的加载、全屏/退出、接线拒绝与撤销、旋钮读数、参数边界、四方向记录和重置。手机端可浏览资料和微观演示，但复杂接线仍应以桌面验收为准。

## 数据与安全

- `HALL_DATA_DIR`：数据目录，默认 `data`。`HALL_UPLOAD_DIR`：附件目录，默认 `uploads`。
- `HALL_DOWNLOAD_DIR`：桌面安装包等公开下载文件目录，默认 `public/downloads`；生产部署示例使用 `/var/lib/hall-downloads`，由 Nginx `/downloads/` 映射，不能放入应用源码树中的敏感目录。
- 本机密钥自动随机生成于 `data/server-secret`；生产设置 `NODE_ENV=production`，必须提供至少48字符随机 `HALL_JWT_SECRET`，由服务器秘密配置管理。密钥变更使全部用户重新登录。
- 新数据库不会自动灌入演示账户。只有明确设置 `HALL_DEMO=1` 才生成演示数据；演示数据不能作为正式成绩。随包历史演示会话已标记隔离。
- 数据库按140至143版本迁移，升级前自动生成 `data/before-v1.4.db`。旧历史孤儿引用或重复项记入审计，不擅自删除；可在教师审计接口或数据库中复核。
- 教师按所管理班级和资源所有者隔离；当前不是学校完整课程/学期/多任课教师教务模型。
- 附件仅通过登录鉴权接口访问。单文件200MB，个人合计1GB。HTML等主动内容拒绝上传，普通文件强制下载。文档格式头检测不代替病毒扫描。
- 备份、凭据与上传目录都不得交给静态Web服务器公开；Windows请为这些目录设置仅运维与服务账号可访问的NTFS权限。
- 公开演示或比赛录屏前，先停止写入并创建备份，然后执行 `node scripts/anonymize-demo-data.cjs <新备份目录>`。该脚本将数据库中的学生姓名、学号、班级和教师姓名稳定映射为“同学1、同学2…”、“1、2…”、“班级1、班级2…”、“教师1…”，同时清理已保存的自由文本身份；用户名和密码保持不变，便于验收登录。脚本输出仅含统计数字，不打印原始身份。它是显式的一次性数据操作，不会在正常启动时自动执行；线上执行时应先停服务，完成备份、脚本和健康检查后再启动。

## 教学流程

教师配置班级、学生、资源与量表，发布并推送资源。学生在试卷服务端截止时间内作答、提交课题，教师进入“教学评阅”处理简答题、课题与实验核验。未核验仿真不计实验成绩。清洗支持保留/排除和原因记录，统计异常是复核提示，不会自动删点；同条件至少5组时使用MAD提示。

分析支持线性、二次、多自变量模型，保存数据快照、清洗证据、哈希、参数、残差、95%区间。不确定度支持重复测量及独立输入量的一阶霍尔系数/浓度传播；相关输入的协方差模型尚不支持。误差限和仪器依据需真实填写。

作品需关联本人正式实验或课题并绑定量表，自动分配最多2位同班评阅人。班级新增学生后教师可在量表页“补齐互评分配”。旧作品迁移保留已有评阅人，优先沿用唯一历史量表；无法确定量表的冲突项留待教师复核后重新发布。申诉可撤销评价，教师确认新成绩后重新发布快照，旧快照不覆盖。

成绩采用版本化固定政策：仿真30%、自测25%、课题30%、互评15%；每卷取最高已阅分再平均，已发布课题全部参与平均，缺交计0；互评质量70%+分配任务完成30%。已提交但未评阅的课题或简答卷会阻止成绩发布，需先完成教学评阅。学校若采用必做/选做、不同权重或重考限制，应先配置开发并经过教学负责人确认，不能假设当前政策适用于所有课程。

`node scripts/install-teaching-files.cjs` 会为课题补充真实任务单，重复执行不重复添加；不是厂家手册。阅读/类比任务已注明引擎不模拟开关阈值、电机换相、流体或量子霍尔。

## 备份恢复

为一致备份附件与数据库，先停止服务并暂停教学写入，再执行 `node scripts/backup.cjs <新备份目录>`。脚本以 SQLite `VACUUM INTO` 生成一致数据库快照，再复制附件并生成 SHA-256 清单；不要在服务运行时仅复制 `hall.db`，WAL 中可能有尚未合入的数据。

恢复命令：`node scripts/restore.cjs <备份目录> <全新恢复目录>`。会先校验所有文件哈希及SQLite完整性，禁止覆盖现有目录。然后将 `HALL_DATA_DIR` 与 `HALL_UPLOAD_DIR` 指向恢复目录中的 `data`、`uploads` 再启动。密钥不备份，恢复生成新密钥或由部署秘密管理系统另行注入，用户重新登录。原数据保留，可在停服后切换环境变量回滚。

## 学校部署

先在隔离环境通过实际班级、目标设备的验收，再用系统服务管理 Node。反向代理到本机 `8182` 并使用 HTTPS，公网只暴露代理端口。Nginx 上传需显式设 `client_max_body_size 210m`，合理配置上传和代理超时；如果允许一次多个附件，需要按实际批次总量调整，不应照搬单文件上限。不得把 JWT 放入 URL。配置日志轮转、磁盘监控和定期恢复演练。

发布脚本 `node scripts/package-release.cjs <输出目录>` 按白名单打包 `server`、`shared`、`dist`、`public/sim` 和部署文件，不包含数据库、上传目录、凭据或 Unity 编辑器缓存；Unity 源工程随 Git 仓库维护，服务器只部署经过验证的 WebGL 产物。Nginx 的 `/sim/` 静态目录应关闭 gzip、sendfile 与 tcp_nopush（Unity 的 `.unityweb` 已是压缩容器，且需要可靠完成 Range 请求），并在每次构建后同步更新页面资源版本号。上线前先生成一致备份，再上传 tar.gz、解压到新的版本目录、执行 `pnpm install --prod --frozen-lockfile`，完成健康检查后原子切换 `current` 符号链接并重启服务。
