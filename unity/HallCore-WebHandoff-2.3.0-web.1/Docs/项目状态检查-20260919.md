## 问题与优先级

### P1：没有版本控制基线

`git log` 显示 master 没有任何提交，`git ls-files` 为 0。源码、场景、配置、说明和工具均未跟踪。现有 Backups 不能提供提交差异、版本溯源或可靠回滚。建议核对纳入清单后提交当前已验证基线，并记录发布包对应提交。

### P2：损坏的最新恢复文件会阻挡更早的有效文件

`WorkbenchUIStyle.cs:152` 的 `InitializeRecovery` 仅选择 `files[0]`；`ExperimentRecovery.Find` 按修改时间倒序列出所有 JSON。恢复失败后弹窗直接关闭，没有尝试下一份，也没有文件选择入口。因此最新 JSON 损坏时，重启仍选同一份文件，更早的有效数据无法从当前 UI 恢复。“稍后处理”同样只有隐藏弹窗的动作，本会话没有重新打开入口。

这是源码确认的控制流问题，本次未通过人工界面复现。建议提供恢复列表、跳过损坏文件及重新打开入口，保留失败文件供排查。

### P2：删除最后一行后的恢复快照可能过期

`HallExperimentModel.cs:130` 的 `SaveData` 只有 `rows.Count > 0` 时才先写恢复文件。可触发的情况：此前 CSV 保存失败，恢复文件含最后一行；用户删除该行，CSV 仍无法保存；此时没有写入空快照，旧恢复文件仍包含已删行。若进程随后崩溃或被强制终止，下次恢复会把已删除行带回。

正常退出路径会再次调用 `PersistRecovery`，因此不能把它概括为每次删除都会失败。这是静态发现的异常退出边界，现有删除检查只覆盖 4 行删到 3 行，没有覆盖删空并保存失败。建议按“数据已变更”决定持久化，而非按行数是否非零。

### P2：工具链不能仅凭仓库内容完整复现

`Tools/render-icons.cjs:3` 直接加载被 `.gitignore` 排除的 `Tools/.runtime/resvg/package/resvgjs.win32-x64-msvc.node`，没有安装脚本或依赖锁定清单。当前电脑具备该文件，换电脑后无法按现有说明重生成图标；已经生成的 PNG 仍可用于正常 Unity 构建。

安装器有 `Tools/InstallerBuild/Setup.cs`、中间 EXE 和 payload ZIP，但未找到自动编译并附加 ZIP、长度及 Marker 的构建脚本。`Package-Teaching.ps1` 只创建并验证发布 ZIP。建议补齐图标依赖初始化与安装器生成命令，并集中管理多处硬编码的 2.2.1 版本号。

### P3：模型范围与维护性仍有边界

- 样品 X/Y 移动目前改变场景位置、机构与软线，不向 `HallExperimentModel.Tick` 传入位置，磁场与读数不随位置变化。若教学目标包含扫描空间磁场，需要补充位置模型；若仅演示机构，应明确说明。
- 模型未实机标定，磁路、浓度、迁移率和噪声包含演示假设，不能作为实机测量准确度结论。README 已说明这一限制。
- 检查以自定义运行脚本为主，未发现 Unity Test Framework 配置或 CI 工作流；可本机验证，但自动回归与干净环境构建流程还不完整。
- UI、运行逻辑和场景生成中存在较多密集单行代码，34 个自有脚本中场景构建与工作台文件较大，后续变更成本偏高。应在功能修复之后逐步整理，不必先大规模重写。
